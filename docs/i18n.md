# Hindi / English (i18n)

Every page can be read in Hindi with the **हिंदी / English** button in the header. The choice is stored in the `rr_lang` cookie (no account needed) and applies to the whole site.

## How it works

- **English is the source.** UI strings stay in English in the code and are wrapped in `t("...")`.
- **Hindi lives in catalogs**: `src/i18n/catalog/*.ts`, one file per area, each a map `"English text": "हिंदी"`.
- **Anything missing falls back to English**, so a page never breaks because a translation is missing.
- Placeholders: `t("Hello, {name}", { name })` with catalog entry `"Hello, {name}": "नमस्ते, {name}"`. Placeholder names must match (a unit test checks this).
- Messages built elsewhere with values already inside (server action results, database errors) still translate if the catalog has a template version: `"We've sent a new verification link to {email}."`.

## In code

| Where | How |
| --- | --- |
| Async server component (pages, layouts) | `const t = await getT();` from `@/i18n/server` |
| Server action / route handler | `const t = await getT();` (only when building a string that isn't returned as-is) |
| Client component (`"use client"`) | `const t = useT();` from `@/i18n/client` |
| Small shared sync server component | `<T>English text</T>` from `@/i18n/client`, or `tx(prop)` from `@/i18n/tx` |
| `export const metadata` titles | `export async function generateMetadata(): Promise<Metadata> { const t = await getT(); return { title: t("...") }; }` |

These shared components translate plain-string props automatically, so callers pass English:
`PageHeader`, `SectionHeading`, `EmptyState`, `StatCard`, `Notice`, `KeyValue`, `Pill` and all status badges, `Field` (label, hint, error), `ChoiceRow`, `FormMessage`, `SubmitButton`, `ActionForm` (label, pending text, confirm text).
Server action messages and validation errors are shown through these, so they only need catalog entries.

Not translated on purpose: the brand name "Rakt Response", blood groups (A+, O−, Bombay "Oh"), people's names, hospital names, and anything a donor or Rakt Mitra typed.

The code and the database still say "volunteer" (`/volunteer`, `staff_roles.role = 'volunteer'`, database messages). `translate()` passes every string through `siteTerms()` in `src/i18n/terms.ts`, so database messages also show "Rakt Mitra"; write new English text with "Rakt Mitra" and the Hindi with रक्त मित्र.

## Hindi style

Write the way people speak: simple, everyday Hindi in short sentences, so donors with less schooling understand it. Use "आप". Avoid heavy Sanskrit words when a common word exists. Keep familiar English words in Devanagari where people already use them.

Glossary, to keep wording consistent:

| English | Hindi |
| --- | --- |
| donor | डोनर |
| blood donation / donate blood | रक्तदान / रक्तदान करें |
| blood | खून (रक्त in compounds: रक्तदान) |
| blood group | ब्लड ग्रुप |
| blood bank / blood centre | ब्लड बैंक |
| whole blood | होल ब्लड |
| platelets / SDP | प्लेटलेट्स / SDP |
| request | रिक्वेस्ट |
| Rakt Mitra (the site's title for a volunteer; plural Rakt Mitras) | रक्त मित्र (रक्त मित्रों) — never स्वयंसेवक or वॉलंटियर |
| admin(istrator) | एडमिन |
| verified / verify | पुष्टि हुई / पुष्टि करें (for records: जाँचा गया) |
| consent | सहमति |
| privacy | प्राइवेसी |
| hospital | अस्पताल |
| eligibility / eligible | योग्यता / रक्तदान कर सकते हैं |
| state / district / city, town, village | राज्य / ज़िला / शहर, कस्बा, गाँव |
| PIN code | पिन कोड |
| email, password, sign in, profile, settings, dashboard | ईमेल, पासवर्ड, साइन इन, प्रोफ़ाइल, सेटिंग्स, डैशबोर्ड |
| story | कहानी |
| camp | कैंप |
| emergency / urgent | इमरजेंसी / जल्दी ज़रूरत |

Avoid gendered verb endings where you can ("आप रक्तदान कर सकते हैं" works for everyone). If unavoidable, use "करता/करती".
Medical and eligibility text: translate faithfully. Never add, soften or strengthen a medical claim.
